Open `migration/src/jvmTest/kotlin/xyz/easiersaid/twr/migration/world/LjmbWorldCandidateValidationTest.kt` and split the existing `assertExpectedLjmbIfrSids` into two `@Test` methods (R3):

- **Coverage test** — uses an `expectedCovered: Set<String> = setOf("GOLV2G", "PETO2B", "PETO5D", "VALU1S", "VALU4L")` value, asserts each is present in `actual`. Catches regressions in the 5 SIDs we promise to keep supporting.

**R2 — set-diff matcher** (applies to coverage test):

```kotlin
// SHAPE ONLY — not implementation; the worker writes the real code:
val missing = expectedCovered - actual
val unexpected = actual - expectedCovered
check(missing.isEmpty() && unexpected.isEmpty()) {
  "LJMB SID coverage drift against CIFP cycle <cycle-id>:\n" +
  "  missing (expected but not present): $missing\n" +
  "  unexpected (present but not expected): $unexpected\n" +
  "If missing is non-empty, a SID we promised to support disappeared from the candidate — " +
  "investigate the generator or CIFP cycle. If unexpected is non-empty, a new SID appeared — " +
  "either widen the expectedCovered set or document the new SID's promise."
}
```

The `<cycle-id>` placeholder is filled from Step 1's CIFP cycle id discovery (e.g. `AIRAC 2511`). Hard-coding the cycle id in the message is fine — it changes infrequently and the next reconciler benefits from seeing the cycle the test was authored against.
